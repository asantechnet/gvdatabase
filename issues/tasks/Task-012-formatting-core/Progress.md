## Decisions and deviations
- `money.ts` deliberately imports nothing so the formatting core is testable without Vite (`import.meta.glob` in the i18n plugin cannot run under plain `tsx`). Active-locale binding lives in `localization.ts`, which remains the single source for the current locale as the task requires.
- Running the app revealed that identical export names in `money.ts` and `localization.ts` made Vite's auto-import pick the locale-blind `money.ts` version. The wrappers were renamed to `formatActiveMoney`/`formatActiveDate`/`formatActiveCount`; explicit imports were unaffected, and auto-import consumers now resolve to the active-locale helpers.
- Placeholder is the em dash `—` for every new helper, documented as `FORMATTING_PLACEHOLDER`; existing `formatLocalizedDate`/`formatLocalizedNumber` keep their current translated placeholder so existing callers do not change.
- Money for a missing/invalid code falls back to a plain localized decimal, without inventing a symbol or duplicating the code.
- The app was started locally for the Task-002 end-to-end run, but money/date output was not visually compared across LTR/Dari/dark; that remains a verification limitation rather than a pass.
